관리자 브라우저

Sequence

사진 한 장의 처리 순서

  1. ESP32-S3카메라 프레임(QVGA 320×240)을 64×64로 줄여 Edge Impulse 사람 감지 모델(FOMO)을 돌린다. 사람이 없으면 아무것도 보내지 않는다.
  2. ESP32-S32프레임 연속 사람이 감지되고 마지막 전송 뒤 5초가 지났으면, 축소 전 원본 JPEG를 POST /frame으로 gateway에 보낸다. 감지 점수·사람 수는 X-Person-Score·X-Person-Count 헤더로 함께 보낸다. 다른 네트워크의 ESP32는 Tailscale Funnel HTTPS 주소로 보내고 X-Device-Token을 붙인다.
  3. gateway프록시(Funnel)를 거친 요청이면 X-Device-Token을 검사해 틀리면 401을 돌려준다. X-Device-Id와 JPEG 형식·크기(2MB 이하)를 검사해 틀리면 400·413을 돌려준다. 통과하면 사진 번호 frame(8자리 hex)과 받은 시각 detected_at을 붙여 대기 줄에 넣고, 판정을 기다리지 않고 바로 202(본문에 frame)를 돌려준다. 대기 줄(4장)이 차 있으면 503을 돌려주고, ESP32는 그 사진을 다시 보내지 않는다.
  4. gateway → inference작업자 1개가 대기 줄에서 한 장씩 꺼내 POST /predict로 보낸다 (헤더 X-Frame-Id, 제한 시간 10초). inference는 YOLOv8 PPE ONNX 모델로 사람·안전모·조끼를 찾아 판정 결과 JSON을 돌려준다.
  5. gateway판정이 pass·no_person이거나 inference 오류면 로그만 남기고 끝낸다. fail이면 판정 결과에 device_id·detected_at·frame_id를 더해 JPEG와 함께 uploader로 넘긴다. 처리 결과는 GET /recent로 최근 50건을 볼 수 있다.
  6. uploader → Supabase받은 기록과 사진을 먼저 ./buffer에 파일로 남긴다. 사진을 violations 버킷에 올리고 공개 URL과 함께 safety_logs에 한 행을 넣는다. 성공하면 버퍼에서 지우고 201, 실패하면 202(buffered)를 돌려주고 30초마다 다시 보낸다. Supabase가 거절한 기록(4xx)은 buffer/failed/로 옮긴다.
  7. 로그세 서비스 로그에 같은 frame=이 찍혀 docker compose logs | grep frame=<번호>로 사진 한 장을 끝까지 따라간다. ESP32 시리얼에는 202 본문의 frame이 찍힌다.
  8. WebRealtime으로 safety_logs INSERT 알림을 받아 위반 수와 목록을 갱신한다.

Components

구성 요소별 역할

gateway

외부 :8001
  • FastAPI. 외부로 열린 유일한 서비스: POST /frame, GET /health(대기 줄 길이·처리 건수), GET /recent(최근 50건, 구간별 시간 wait_ms·infer_ms·upload_ms·total_ms).
  • 같은 LAN 요청은 토큰 없이, 프록시 헤더가 붙은 인터넷 요청은 X-Device-Token을 검사한다. GATEWAY_TOKEN이 비어 있으면 인터넷 요청은 모두 401.
  • asyncio.Queue(maxsize=QUEUE_MAX)(기본 4) + 처리 작업자 1개.
  • inference와 uploader를 부르는 순서를 이곳에서만 정한다. 제한 시간은 inference 10초, uploader 15초.

inference

내부 :8003
  • POST /predict: JPEG를 받아 판정 JSON을 돌려준다. 다른 서비스를 부르지 않는다.
  • 모델은 서버 시작 때 한 번만 불러온다. uvicorn worker는 1개.
  • 패키지: onnxruntime, numpy, opencv-python-headless, fastapi, uvicorn.
  • GET /health는 모델이 없어도 200(model_loaded: false)을 준다. 모델이 없을 때 판정 요청은 503.

uploader

내부 :8004
  • POST /records: 판정 JSON + JPEG를 받아 Supabase에 저장한다. 저장하면 201, 버퍼에 남기면 202.
  • 받은 기록은 먼저 ./buffer에 {id}.json·{id}.jpg로 남기고, 보내는 데 성공하면 지운다. 남은 것은 RETRY_INTERVAL(30초)마다 다시 보낸다.
  • Supabase service key를 가진 유일한 컨테이너. .env가 없으면 받은 기록을 버퍼에만 쌓는다.

Supabase 저장 구조

safety_logs
  • id bigint identity, 기본 키
  • created_at timestamptz, gateway가 사진을 받은 시각(detected_at). 버퍼에서 늦게 올라가도 유지
  • device_id text
  • has_helmet, has_vest boolean
  • confidence real
  • image_url text, violations 버킷 공개 URL. 경로는 {device_id}/{YYYY-MM-DD}/{uuid}.jpg
Deployment

docker-compose와 폴더 구조

# pi/docker-compose.yml (요약)
services:
  gateway:
    build: ./gateway
    ports: ["8001:8001"]   # 외부로 여는 유일한 포트
    environment:
      INFERENCE_URL: http://inference:8003
      UPLOADER_URL: http://uploader:8004
      GATEWAY_TOKEN: ${GATEWAY_TOKEN:-}   # pi/.env, 인터넷 요청 검사
    depends_on: [inference, uploader]
    mem_limit: 256m

  inference:
    build: ./inference
    volumes: ["./models:/models:ro"]
    environment:
      MODEL_PATH: /models/ppe_yolov8.onnx
    mem_limit: 1g

  uploader:
    build: ./uploader
    env_file:              # SUPABASE_URL, SUPABASE_SERVICE_KEY
      - path: .env
        required: false
    volumes: ["./buffer:/buffer"]
    mem_limit: 256m

# 세 서비스 공통: restart: unless-stopped,
# healthcheck = GET /health (15초 간격),
# environment: TZ=Asia/Seoul, LOG_LEVEL, COMMIT
# logging: json-file 10MB × 3

  • 베이스 이미지는 python:3.12-slim(arm64 제공)이고, 이미지는 파이에서 docker compose up --build로 직접 빌드한다.
  • Pi 배포는 GitHub Actions deploy-pi(Pi의 self-hosted runner)로 팀원 누구나 한다. 브랜치를 골라 받고 다시 빌드하며, 시작 로그에 commit=이 찍힌다. 쓰는 법은 pi/README.md.
  • 로그 시각은 한국 시각(TZ), JSON 안의 시각(detected_at, created_at)은 UTC다.
  • ultralytics와 torch는 PC에서 ONNX로 변환할 때만 쓰고, 파이 이미지에는 넣지 않는다.
  • inference의 ORT_THREADS(3), CONF_THRES(0.4), IOU_THRES(0.45), gateway의 QUEUE_MAX(4)는 코드 기본값이다. 바꿀 때만 compose environment에 적는다.
  • mem_limit 값은 시작값이다. docker stats로 실제 사용량을 확인해 조정한다.
  • inference와 uploader는 compose 내부망에서만 접근된다. 인터넷에는 Tailscale Funnel로 gateway(8001)만 열린다. SSH 등 다른 포트는 열지 않는다.
저장 범위: 위반(fail) 건만 Supabase에 기록과 사진을 저장한다. pass·no_person 건은 gateway 로그와 GET /recent에만 남는다.
