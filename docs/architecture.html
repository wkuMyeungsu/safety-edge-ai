안전장비 감지 시스템 구조

ESP32-S3가 사람을 감지한 프레임만 라즈베리 파이 5로 보내고, 파이는 안전모·조끼 착용 여부를 판별해 위반 건을 Supabase에 기록한다. 웹은 Supabase를 직접 조회해 위반 기록을 보여 준다.

관리자 브라우저

Sequence

사진 한 장의 처리 순서

  1. ESP32-S3카메라 프레임을 96×96으로 줄여 Edge Impulse 사람 감지 모델을 돌린다. 사람이 없으면 아무것도 보내지 않는다.
  2. ESP32-S3사람이 감지되고 마지막 전송 뒤 3초가 지났으면, 축소 전 원본 JPEG를 POST /frame으로 gateway에 보낸다.
  3. gateway대기 줄에 자리가 있으면 받아 넣고 202를 돌려준다. 대기 줄이 차 있으면 503을 돌려주고 사진을 버린다. 받은 수와 버린 수는 로그로 남긴다.
  4. gateway → inference대기 줄에서 꺼낸 사진을 POST /predict로 보낸다. inference는 YOLOv8 PPE ONNX 모델로 안전모·조끼를 찾아 판정 결과 JSON을 돌려준다.
  5. gateway판정이 pass면 로그만 남기고 끝낸다. fail이면 판정 결과와 JPEG를 uploader로 넘긴다.
  6. uploader → Supabase사진을 violations 버킷에 올리고, 받은 URL과 함께 safety_logs에 한 행을 넣는다. 실패하면 ./buffer에 저장해 두고 재시도한다.
  7. WebRealtime으로 새 행 알림을 받아 목록과 오늘 위반 수를 갱신한다.

Components

구성 요소별 역할

gateway

외부 :8001
  • FastAPI, POST /frame 하나만 외부에 연다.
  • asyncio.Queue(maxsize=2) + 처리 작업자 1개.
  • inference와 uploader를 부르는 순서를 이곳에서만 정한다.

inference

내부 :8003
  • POST /predict: JPEG를 받아 판정 JSON을 돌려준다. 다른 서비스를 부르지 않는다.
  • 모델은 서버 시작 때 한 번만 불러온다. uvicorn worker는 1개.
  • 패키지: onnxruntime, numpy, opencv-python-headless, fastapi, uvicorn.
  • GET /health로 healthcheck.

uploader

내부 :8004
  • POST /records: 판정 JSON + JPEG를 받아 Supabase에 저장한다.
  • 네트워크 오류 때는 ./buffer에 파일로 남기고 주기적으로 다시 보낸다.
  • Supabase service key를 가진 유일한 컨테이너.

Supabase 저장 구조

safety_logs
  • id bigint identity, 기본 키
  • created_at timestamptz, 기본값 now()
  • device_id text
  • has_helmet, has_vest boolean
  • confidence real
  • image_url text, violations 버킷 경로
Deployment

docker-compose와 폴더 구조

services:
  gateway:
    build: ./services/gateway
    ports: ["8001:8001"]
    environment:
      INFERENCE_URL: http://inference:8003
      UPLOADER_URL: http://uploader:8004
      QUEUE_MAX: "2"
    depends_on: [inference, uploader]
    mem_limit: 256m
    restart: unless-stopped

  inference:
    build: ./services/inference
    volumes: ["./models:/models:ro"]
    environment:
      MODEL_PATH: /models/ppe_yolov8.onnx
      ORT_THREADS: "3"
      CONF_THRES: "0.4"
    mem_limit: 1g
    cpus: "3"
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "python", "-c",
        "import urllib.request;urllib.request.urlopen('http://localhost:8003/health')"]
      interval: 15s

  uploader:
    build: ./services/uploader
    env_file: .env     # SUPABASE_URL, SUPABASE_SERVICE_KEY
    volumes: ["./buffer:/buffer"]
    mem_limit: 256m
    restart: unless-stopped

  • 베이스 이미지는 python:3.11-slim(arm64 제공)이고, 이미지는 파이에서 docker compose build로 직접 빌드한다.
  • ultralytics와 torch는 PC에서 ONNX로 변환할 때만 쓰고, 파이 이미지에는 넣지 않는다.
  • mem_limit 값은 시작값이다. docker stats로 실제 사용량을 확인해 조정한다.
  • 외부로 열리는 포트는 gateway의 8001뿐이다. inference와 uploader는 compose 내부망에서만 접근된다.
저장 범위: 위반(fail) 건만 Supabase에 기록과 사진을 저장한다. pass 건은 gateway 로그에만 남는다.
