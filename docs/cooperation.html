원격 테스트 환경 (Tailscale Funnel)

목적

  • Pi는 현장 LAN에 1대만 설치되어 있어, 외부 네트워크의 팀원은 Pi에 직접 접근할 수 없음.
  • Tailscale Funnel로 gateway를 인터넷에 공개하여, 팀원이 위치와 관계없이 실제 Pi로 테스트할 수 있게 함.
  • 외부에서 보낸 사진도 현장 사진과 동일하게 판정·저장되므로, 실제 시스템과 같은 조건으로 검증 가능.

담당별 활용 예시

담당테스트 구간방법확인 항목
esp32 (대희)ESP32 → gateway본인 ESP32에서 Funnel 주소로 전송시리얼의 202·frame, /recent의 감지 점수·사람 수
inference (우진)gateway → inferencedeploy-pi로 추론 코드 배포 후 시험 사진 전송/recent의 판정 결과, Pi 실측 infer_ms
uploader·cloud (도은)gateway → uploader → Supabase위반 사진(fail) 전송safety_logs 행, violations 버킷 사진, uploader 로그의 log_id
web (진아)Supabase → 웹test- 장치 ID로 위반 사진 전송웹 목록·수치의 실시간 갱신, 사진 표시, 장치 필터
gateway·배포 (명수)전체 흐름Funnel 경유 요청, 연속 요청토큰 불일치 시 401, 대기 줄 초과 시 503, 배포 후 commit=
  • 모든 담당이 PC에서 curl로 사진을 보내 실제 Pi의 전체 흐름(판정 → 저장 → 웹 표시)을 확인할 수 있음.
  • 코드 변경을 실제 Pi에서 확인하려면 3절의 deploy-pi로 먼저 배포.
  • 시험 기록은 장치 ID를 test-로 시작하여 운영 기록과 구분.

접근 제어 (토큰)

  • Funnel 주소는 인터넷에 공개되어 있어, 주소를 아는 누구나 요청할 수 있음.
  • 인증이 없으면 외부인의 사진이 판정되어 Supabase와 웹에 잘못된 위반 기록이 남을 수 있음.
  • 대량 요청 시 대기 줄이 가득 차서 팀 장치의 사진이 503으로 거절될 수 있음.
  • 이를 막기 위해 외부 요청은 팀 공용 토큰이 일치할 때만 처리하고, 불일치 시 401을 반환함.
  • LAN 요청은 같은 네트워크의 장치로 한정되므로 토큰 검사를 생략함.

Pi 배포 (deploy-pi)

목적

  • Funnel은 사진 수신만 허용하므로, 수정한 코드를 Pi에 반영하는 별도 경로가 필요함.
  • SSH는 Pi 전체 권한을 부여하게 되어 사용하지 않음.
  • Pi에 설치한 GitHub Actions runner가 GitHub에서 작업을 받아 실행하는 방식으로, 새 포트를 열지 않고 배포함.

사용 방법

GitHub → Actions → deploy-pi → Run workflow에서 브랜치와 동작을 선택.

동작내용
deploy선택한 브랜치를 Pi에 배포. 이후 30분간 다른 사용자의 배포 제한
status변경 없이 현재 커밋, 사용 중인 사람, 컨테이너 상태, 최근 로그 조회
release사용 표시 해제. 다른 사용자 배포 가능
  • 배포 후 테스트는 2절의 방법으로 진행.
  • 다른 사용자가 사용 중이면 즉시 실패하며, 실행 화면 상단 Summary에 사용자와 해제 시각 표시.
  • 테스트 종료 후 release 실행, dev 재배포.
  • 모델 파일과 .env는 배포 대상이 아님. 변경이 필요하면 Pi 관리자에게 요청.

협업 규칙

담당

  • 본인 담당 폴더만 수정
  • 타 담당 폴더 수정이 필요하면 담당자와 협의
  • 담당 범위: README "폴더별 담당"

브랜치

  • 형식: 태그/파트/기능
  • 예: feature/pi/gateway-queue
  • main, dev 직접 push 금지

커밋

  • 형식: 타입(파트): 요약
  • 예: feat(pi): 대기 줄 추가
  • 계약 변경 시 [contract] 표기

CI

  • PR 생성 시 변경된 파트만 검사
  • ci-ok 성공 시 병합 가능
  • 계약 문서 변경 시 전체 파트 검사

테스트

  • 위치: tests/파트/test_*.py
  • 서비스 코드 import 금지, HTTP 요청으로 검증
  • 마커: model, supabase, pi

계약

  • 구현 전 docs/contracts/에 형식 정의
  • 송신·수신 담당자 모두 확인
  • 배포는 수신 측부터 진행

커밋 제외 파일

  • 비밀값: .env, config.h, 토큰
  • 대용량: 모델 가중치, 영상
  • 실행 산출물: pi/buffer/, 로그 파일

기록

  • 측정값은 측정 커밋과 함께 기록
  • 주요 결정은 decisions.md에 기록

로컬 테스트

  • pi 폴더에서 CI 설정으로 컨테이너 실행
  • 저장소 루트에서 pytest tests/pi tests/e2e 실행
  • 상세 명령: tests/README.md
원본 문서: CLAUDE.md, README.md, pi/README.md. 규칙 변경 시 함께 수정.
