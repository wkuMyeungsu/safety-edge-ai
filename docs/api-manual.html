10-00-00

일반 (설명과 작동)

1. 목적

이 교범은 라즈베리 파이 gateway가 제공하는 API와, 그 API를 쓰는 작업 절차를 정한다. 대상은 팀원 전원이다.

2. 시스템 구성

[ESP32 / PC] ──JPEG──▶ gateway :8001 ──▶ inference :8003 (안전모·조끼 판정)
                           │
                           └─(위반이면)──▶ uploader :8004 ──▶ Supabase (safety_logs, violations 버킷) ◀── 웹
  • gateway는 사진을 받으면 대기 줄에 넣고 바로 202로 답한다. 판정은 기다리지 않는다.
  • 작업자 1개가 대기 줄에서 한 장씩 꺼내 inference에 판정을 맡긴다.
  • 판정이 fail이면 uploader에 넘긴다. uploader가 Supabase에 저장한다.
  • 판정 결과는 ESP32에 돌려주지 않는다. GET /recent, Supabase, 웹에서 본다.

3. 접근 경로

경로주소토큰쓰는 곳
같은 네트워크http://172.30.1.68:8001필요 없음명수 집 네트워크의 ESP32·PC
인터넷 (Tailscale Funnel)https://rpi5.tail7377e4.ts.netPOST /frame에만 필요다른 곳의 ESP32·PC
참고 NOTE

Pi 주소 172.30.1.68은 공유기 DHCP 예약 전에는 바뀔 수 있다. 바뀌면 이 표를 개정한다.

참고 NOTE

외부에 열린 것은 gateway(8001)뿐이다. inference, uploader, SSH는 인터넷에서 접근할 수 없다.

4. 인증

요청인증
같은 네트워크의 모든 요청없음
인터넷의 GET /health, GET /recent없음 (공개)
인터넷의 POST /frameX-Device-Token 헤더가 Pi pi/.env의 GATEWAY_TOKEN과 같아야 한다
  • gateway는 프록시 헤더(X-Forwarded-For, Forwarded, Cf-Connecting-Ip, Tailscale-Funnel-Request)가 있으면 인터넷 요청으로 본다.
  • GATEWAY_TOKEN이 비어 있으면 인터넷의 POST /frame은 모두 401이다.
⚠ 경고 WARNING

토큰을 커밋, PR, 이슈, 공개 채팅에 쓰지 않는다. 토큰은 Pi pi/.env와 각자의 config.h에만 둔다. 명수에게 개인 메시지로 받는다.

△ 주의 CAUTION

인터넷의 GET /health, GET /recent는 토큰 없이 누구나 볼 수 있다. 장치 ID와 판정 결과가 보인다. 장치 ID에 개인정보를 넣지 않는다.

5. 공통 규칙

항목규칙
응답 형식JSON (Content-Type: application/json)
시각UTC, ISO 8601 (예: 2026-11-02T04:22:10.873519+00:00)
장치 ID영문·숫자·-·_, 1~64자. 팀원 ESP32는 cam-<이름>, 테스트는 test-<아무거나> (docs/contracts/frame.md)
사진JPEG 바이트 그대로, 2MB 이하
⚠ 경고 WARNING

위반으로 판정된 사진은 실제 Supabase에 저장되고 웹에 나온다. 시험 전송에는 반드시 test-로 시작하는 장치 ID를 쓴다. 그래야 시험 기록만 골라 지울 수 있다.

장비용도

  1. 장비가 Pi와 같은 네트워크에 있는지 확인한다.

G.마무리

1. GET /health 응답 (200)

필드형식뜻
service문자열항상 "gateway"
status문자열항상 "ok" (답하면 살아 있는 것)
queue정수대기 중인 사진 수
queue_max정수대기 줄 크기 (QUEUE_MAX, 기본 4)
stats객체gateway 시작 후 누적 건수. 0인 항목은 빠진다
stats 키뜻
received대기 줄에 넣은 사진
rejected400·413으로 거절
unauthorized401로 거절 (토큰)

upload_stored · upload_buffered · upload_error위반 저장 결과별

2. GET /recent 응답 (200)

질의 변수: device_id (선택). 응답: {"items": [ ... ]}, 최근 것부터, 최대 50건.

필드형식뜻
device_id문자열보낸 장치
received_at문자열 (UTC)gateway가 받은 시각. Supabase created_at이 된다
wait_ms정수대기 줄에서 기다린 시간
person_score숫자 | nullESP32 사람 감지 점수 (X-Person-Score)
person_count정수 | nullESP32가 찾은 사람 수 (X-Person-Count)
verdict문자열pass · fail · no_person · error
has_helmetbool모두 안전모를 썼는지 (판정 실패면 없음)
has_vestbool모두 조끼를 입었는지 (판정 실패면 없음)
confidence숫자판정 신뢰도 0~1 (판정 실패면 없음)
infer_ms정수inference 추론 시간 (판정 실패면 없음)
upload문자열 | nullstored · buffered · error. 위반이 아니면 null

3. POST /frame

요청 헤더

헤더필수값
Content-Type예image/jpeg
X-Device-Id예장치 ID (10-00-00 5항)
X-Device-Token인터넷이면 예팀 공용 토큰
X-Person-Score아니오0~1. 숫자가 아니면 null로 기록하고 사진은 받는다
X-Person-Count아니오정수. 숫자가 아니면 null로 기록하고 사진은 받는다

본문: JPEG 바이트 그대로 (FF D8 FF로 시작), 2MB 이하. multipart가 아니다.

응답

코드본문 status뜻보낸 쪽이 할 일
202queued대기 줄에 넣음. queue는 지금 대기 수없음
400rejected장치 ID 형식 틀림, 본문이 JPEG가 아님버린다. detail을 보고 설정을 고친다
401rejected인터넷 요청인데 토큰이 없거나 틀림버린다. 토큰을 확인한다
413rejected2MB 초과버린다. 해상도·품질을 낮춘다
503busy대기 줄 가득 참버린다. 다시 보내지 않는다 (다음 프레임이 더 최신)

오류 본문은 {"status": "...", "detail": "<이유>"}.

40-00-00

고장 탐구 (Fault Isolation)

먼저 20-10-01로 gateway가 답하는지 확인한다. 답하지 않으면 1번부터 본다.

번호증상가능한 원인조치
1인터넷 주소가 응답 없음, TLS 오류Pi 꺼짐, 네트워크 끊김, Funnel 꺼짐명수에게 알린다. 명수는 Pi에서 tailscale funnel status, docker compose ps를 확인한다
2같은 네트워크 주소가 응답 없음Pi IP 바뀜, 다른 네트워크에 있음ping rpi5.local 또는 공유기에서 Pi IP를 확인한다
