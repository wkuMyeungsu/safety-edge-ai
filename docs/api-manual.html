Pi gateway API

라즈베리 파이 gateway에 사진을 보내 안전모·조끼 판정을 받고, 결과를 조회하는 API.

주소와 인증

어디서기본 주소토큰
Pi와 같은 네트워크http://172.30.1.68:8001필요 없음
인터넷 (그 밖의 곳)https://rpi5.tail7377e4.ts.netPOST /frame만 X-Device-Token 필요
  • 토큰은 명수에게 개인 메시지로 받는다. 커밋하거나 공개 채널에 올리지 않는다.
  • 장치 ID: 팀원 ESP32는 cam-<이름>, 시험 전송은 test-<아무거나>.

위반으로 판정된 사진은 실제 Supabase에 저장되고 웹에 나온다. 시험할 때는 test- 장치 ID를 쓴다.

엔드포인트

POST/frame사진 보내기 (판정 요청)
헤더필수값
Content-Type예image/jpeg
X-Device-Id예영문·숫자·-·_, 1~64자
X-Device-Token인터넷이면 예팀 공용 토큰
X-Person-Score, X-Person-Count아니오ESP32 사람 감지 점수(0~1)와 사람 수. 기록만 한다

본문은 JPEG 바이트 그대로 (multipart 아님), 2MB 이하. 바로 202로 답하고 판정은 뒤에서 한다.

curl -H "X-Device-Id: test-woojin" -H "X-Device-Token: <토큰>" -H "Content-Type: image/jpeg" \
     --data-binary @사진.jpg https://rpi5.tail7377e4.ts.net/frame

필드값
verdictfail 위반 · pass 정상 · no_person 사람 없음 · error 판정 실패
uploadstored Supabase 저장 · buffered Pi에 보관 후 나중에 저장 · error 저장 실패 · null 위반 아님
has_helmet, has_vest, confidence, infer_ms판정 결과 (판정 실패면 없음)
received_at받은 시각, UTC

gateway를 다시 시작하면 비워진다. 오래 남길 기록은 Supabase와 웹에서 본다.

GET/health상태 확인
{"service": "gateway", "status": "ok", "queue": 0, "queue_max": 4,
 "stats": {"received": 18, "verdict_fail": 11, "verdict_pass": 5, "upload_stored": 1, "unauthorized": 2}}

queue가 queue_max와 같으면 새 사진은 503으로 거절된다. stats는 시작 후 누적 건수.

응답 코드 (POST /frame)

코드뜻할 일
202받음 (대기 줄에 넣음)/recent로 결과 확인
400장치 ID 형식이 틀림, 본문이 JPEG가 아님detail을 보고 고친다
401인터넷 요청인데 토큰이 없거나 틀림토큰 확인
4132MB 초과해상도·품질을 낮춘다
503대기 줄이 가득 참버리고 다음 사진을 보낸다

오류 본문: {"status": "rejected" | "busy", "detail": "<이유>"}
